Applied:

1. **A bad file no longer falls back.** `vite.config.ts` returns null only for
   `ENOENT` and rethrows anything else. `resolveSourceCommitHash` throws when the
   file holds something that is not a commit hash, with a message naming the
   file. Three tests cover it.
2. **Nothing is shortened any more.** The resolver returns the value it validated.
   The deploy workflow now writes `git rev-parse --short "$GITHUB_SHA"`, so the
   file holds the same length git would have printed, and a local build keeps
   git's own length (8 here). Tests pin both lengths coming back untouched.
3. **Dockerfile warning** now reads
   `{ git rev-parse --short HEAD >/dev/null 2>&1 || [ -f .source-commit ]; } ||
   echo "WARNING: no usable git repository and no .source-commit ..."`. I checked
   the three cases in bash: git present (silent), no git and no file (warns), no
   git and file present (silent).
4. **`docs/overview.md`** `build.gitCommit` row now says what the field is.
5. **Changelog** blank line between the bullets of that day removed.
